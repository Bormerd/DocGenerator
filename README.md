## Описание проекта

Программа предназначена для упрощения создания документации программных проектов.

DocGenerator анализирует исходный код, извлекает информацию о классах, функциях, методах и их параметрах, получает описания из комментариев и формирует Markdown-документ.

Программа поддерживает обработку отдельных файлов и целых каталогов с исходным кодом.

## Функциональные возможности

### Анализ Python

- Анализ исходного кода с помощью стандартного модуля `ast`.
- Поиск классов и функций верхнего уровня.
- Получение методов классов.
- Извлечение параметров функций и методов.
- Получение аннотаций типов и значений параметров по умолчанию.
- Извлечение возвращаемых аннотаций.
- Получение описаний из `docstring`.

### Анализ JavaScript

- Поиск объявлений функций и классов, перед которыми находятся JSDoc-комментарии.
- Извлечение описаний из JSDoc.
- Получение параметров и их типов из тегов `@param`.
- Получение возвращаемого типа из тегов `@return` и `@returns`.
- Использование объявленных параметров функции, если параметры не указаны в JSDoc.

### Генерация документации

- Создание документации в формате Markdown.
- Использование собственного Markdown-шаблона.
- Обработка отдельных файлов.
- Обработка каталогов с Python- и JavaScript-файлами.
- Объединение документации нескольких файлов в один документ.

### Проверка Markdown

Перед возвратом результата программа проверяет:

- Наличие содержимого.
- Наличие заголовка первого уровня.
- Парность маркеров блоков кода.
- Отсутствие незаполненных шаблонных переменных.

## Установка и запуск

Для работы необходим Python версии 3.12 или выше.

### 1. Клонирование репозитория

```bash
git clone https://github.com/Bormerd/DocGenerator.git
cd DocGenerator
```

### 2. Создание виртуального окружения

```bash
python -m venv .venv
```

### 3. Активация виртуального окружения

Для Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

### 4. Установка инструментов

```bash
pip install pytest ruff pre-commit
```

### 5. Запуск программы

Из корневой папки проекта в Windows PowerShell:

```powershell
$env:PYTHONPATH = "src"
python -m docgenerator.main путь_к_файлу_или_папке
```

Пример обработки Python-файла:

```powershell
$env:PYTHONPATH = "src"
python -m docgenerator.main example.py
```

Пример обработки JavaScript-файла:

```powershell
$env:PYTHONPATH = "src"
python -m docgenerator.main example.js
```

Пример обработки целого проекта:

```powershell
$env:PYTHONPATH = "src"
python -m docgenerator.main ./src -o DOCUMENTATION.md
```

## Параметры командной строки

| Параметр | Описание |
|---|---|
| `path` | Путь к исходному файлу или каталогу |
| `-t`, `--template` | Путь к Markdown-шаблону |
| `-o`, `--output` | Имя выходного файла. По умолчанию `README.md` |

Пример использования собственного шаблона:

```powershell
$env:PYTHONPATH = "src"
python -m docgenerator.main ./src -t templates/default.md -o DOCUMENTATION.md
```

## Шаблоны документации

Для формирования документации используется Markdown-шаблон.

По умолчанию программа использует файл:

```text
templates/default.md
```

В шаблоне поддерживаются следующие переменные:

| Переменная | Назначение |
|---|---|
| `{{ file }}` | Имя анализируемого файла |
| `{{ classes }}` | Информация о найденных классах |
| `{{ functions }}` | Информация о найденных функциях |

Пример шаблона:

```markdown
# Документация проекта

Файл: {{ file }}

## Классы

{{ classes }}

## Функции

{{ functions }}
```

## Проверка проекта

Для запуска автоматических тестов используется pytest:

```powershell
pytest
```

Проверка стиля кода:

```powershell
ruff check .
```

Проверка форматирования:

```powershell
ruff format --check .
```

## Автоматическая проверка

В проекте настроен GitHub Actions.

При отправке изменений в ветку `main` и создании Pull Request запускаются следующие проверки:

1. Получение исходного кода проекта.
2. Установка Python 3.12.
3. Проверка стиля кода с помощью Ruff.
4. Проверка форматирования.
5. Запуск автоматических тестов с помощью pytest.

Автоматическая проверка позволяет выявлять ошибки и проблемы со стилем кода при разработке проекта.
